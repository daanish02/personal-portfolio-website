## What It Does

ArcPublish is designed around a simple workflow:

```text
Generate ideas
      ↓
Select topic
      ↓
Research
      ↓
Generate content
      ↓
Adapt for each platform
      ↓
Review in Telegram
      ↓
Approve
      ↓
Publish
```

Instead of manually creating three versions of the same idea, the system produces platform-specific content:

| Platform | Output                      |
| -------- | --------------------------- |
| LinkedIn | Professional long-form post |
| X        | Tweet / thread              |
| Medium   | Long-form article           |

Nothing is published without explicit approval.

## Architecture

The system is separated into several components.

```text
Telegram
   │
   ▼
Application Layer
   │
   ▼
LangGraph Workflow
   │
   ├── Topic Agent
   ├── Research Agent
   ├── Writer Agent
   ├── Editor Agent
   └── Distribution Agent
          │
          ▼
     Publisher Layer
          │
     ┌────┼────┐
     ▼    ▼    ▼
 LinkedIn X  Medium
```

### Agent Layer

The AI workflow is responsible for:

* topic generation
* research
* content generation
* platform adaptation
* editing
* quality checks

### Control Layer

Telegram provides:

* topic selection
* content previews
* regeneration
* approval
* rejection
* publishing control

### Publisher Layer

Each platform has an independent publishing adapter:

```text
publishers/
├── linkedin.py
├── x.py
└── medium.py
```

This keeps platform-specific API logic isolated from the AI workflow.

## Human-in-the-Loop

Autonomous publishing is deliberately avoided.

The system follows:

```text
AI proposes
     ↓
Human reviews
     ↓
Human approves
     ↓
System executes
```

This makes the architecture suitable for organizations where generated content requires editorial or brand approval.

## Design Principles

### Platform-independent AI

The content generation system does not directly depend on a particular social platform.

```text
AI Workflow
     ↓
Content Model
     ↓
Platform Adapter
```

This makes it possible to add additional publishing destinations without modifying the core agent workflow.

### Explicit approval

Publishing is an irreversible external action, so it requires an explicit approval event.

### Modular publishers

Adding a new platform should require implementing a publisher adapter rather than modifying the entire system.

```python
class Publisher:
    def publish(self, content):
        ...
```

### Structured AI output

Agents produce structured content rather than arbitrary text, allowing downstream validation before publication.

---

### One thing I would change from the earlier concept

I would **not** make the README's main pitch:

> “An AI tool that automatically posts to LinkedIn, X and Medium.”

That is too easy to compare with n8n, Buffer, Zapier, etc.

I'd position it as:

> **“An agentic content operations system with human-controlled execution.”**

The social platforms are merely the **first use case**. The interesting engineering is the workflow underneath: research → reasoning → generation → validation → approval → execution → feedback.

That also gives Arc Systems room to demonstrate that the same architecture can eventually be applied to **sales operations, customer support, research, internal knowledge workflows, reporting, and other business processes**, rather than making the agency look like a social-media automation company.

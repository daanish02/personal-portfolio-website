# HR RAG Assistant

A secure Retrieval-Augmented Generation (RAG) system for answering employee and HR questions using company policies, handbooks, benefits documents, and HRMS data.

The system combines **document retrieval, permission-aware search, LLM-based answer generation, and HRMS APIs** to provide accurate answers with citations while preventing unauthorized access to sensitive employee information.

## Key Design Principle

The LLM is **not responsible for authorization**.

Permissions are applied before documents are passed to the model.

```text
User
  │
  ▼
Authentication
  │
  ▼
Determine permissions
  │
  ▼
Filter searchable documents
  │
  ▼
Retrieve authorized documents
  │
  ▼
LLM
```

This prevents a model from receiving confidential information that the user is not authorized to access.

## Document Ingestion

HR documents are processed through the following pipeline:

```text
PDF / DOCX / HTML
        │
        ▼
   Text Extraction
        │
        ▼
      Cleaning
        │
        ▼
 Structure Detection
        │
        ▼
      Chunking
        │
        ▼
 Metadata Extraction
        │
        ▼
     Embeddings
        │
        ▼
 PostgreSQL + pgvector
```

Each chunk contains metadata such as:

```json
{
  "document_id": "leave-policy-2026",
  "title": "Annual Leave Policy",
  "section": "Carry Forward",
  "version": "2026.1",
  "country": "India",
  "classification": "internal",
  "effective_date": "2026-01-01",
  "allowed_roles": [
    "employee",
    "manager",
    "hr"
  ]
}
```

## Retrieval Pipeline

The system uses hybrid retrieval:

```text
User Query
    │
    ├──────────────► Vector Search
    │
    └──────────────► Keyword Search
                          │
                          ▼
                    Merge Results
                          │
                          ▼
                       Reranker
                          │
                          ▼
                    Top K Chunks
                          │
                          ▼
                         LLM
```

This allows the system to handle both semantic questions and exact HR terminology such as:

```text
EPF
PF
notice period
PIP
₹15,000
Form 16
```

## Policy Versioning

Documents are versioned rather than overwritten.

```text
Annual Leave Policy
│
├── v1.0
│   effective: 2025-01-01
│
└── v2.0
    effective: 2026-01-01
    active: true
```

The retrieval layer selects the policy applicable to the user's location and the requested date.

## Access Control

Documents can contain metadata such as:

```json
{
  "classification": "confidential",
  "allowed_roles": [
    "hr_admin"
  ]
}
```

Example roles:

```text
EMPLOYEE
MANAGER
HR
HR_ADMIN
```

Access is enforced during retrieval.

An employee asking:

```text
Show me John's salary.
```

must not cause John's salary record to be retrieved and subsequently filtered by the LLM.

## RAG Prompting

The generation layer follows rules such as:

```text
You are an HR assistant.

Answer using only the supplied sources.

Rules:
- Do not invent company policies.
- Do not disclose unauthorized information.
- Prefer the currently effective policy.
- If the sources do not contain the answer, state that the
  information could not be found.
- Cite the source document and section.
```

## RAG vs HRMS

Not every HR question should use RAG.

| Question                          | Mechanism                |
| --------------------------------- | ------------------------ |
| What is the leave policy?         | RAG                      |
| What is the maternity policy?     | RAG                      |
| How many leave days do I have?    | HRMS API                 |
| When does my probation end?       | HRMS API                 |
| What is my salary?                | HRMS API + authorization |
| What changed in the leave policy? | RAG                      |
| Start a leave request             | HRMS workflow/API        |

The query router determines which system should handle the request.

## Security

Because this system handles HR information, security is a first-class requirement.

The system should provide:

* SSO authentication
* RBAC / ABAC
* Retrieval-time authorization
* Encryption in transit
* Encryption at rest
* Secure secret management
* Audit logging
* PII handling
* Prompt-injection defenses
* Data retention controls
* LLM provider data-retention controls

## Running Locally

### 1. Clone the repository

```bash
git clone <repository-url>
cd hr-rag
```

### 2. Create the environment

```bash
python -m venv .venv

source .venv/bin/activate
```

Windows:

```bash
.venv\Scripts\activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure environment variables

```bash
cp .env.example .env
```

Configure:

```text
DATABASE_URL=
LLM_API_KEY=
EMBEDDING_API_KEY=
HRMS_API_URL=
HRMS_API_KEY=
JWT_SECRET=
```

### 5. Start PostgreSQL

```bash
docker compose up -d postgres
```

### 6. Run migrations

```bash
alembic upgrade head
```

### 7. Ingest HR documents

```bash
python -m app.ingestion.pipeline
```

### 8. Start the API

```bash
uvicorn app.main:app --reload
```

API documentation:

```text
http://localhost:8000/docs
```

## Design Goals

The system prioritizes:

1. **Security** — unauthorized HR information must never reach the model.
2. **Accuracy** — answers should be grounded in company sources.
3. **Traceability** — users should be able to see where answers came from.
4. **Freshness** — current policy versions should take precedence.
5. **Reliability** — the system should say when it doesn't know.
6. **Maintainability** — HR should be able to update documents without modifying application code.
